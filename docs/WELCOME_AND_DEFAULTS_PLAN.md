# Welcome page, default slideshow, global defaults and page defaults (plan)

Planned with the owner on 2026-10-07, in small confirmed steps. The epic [camera#332](https://github.com/moldovancsaba/camera/issues/332) tracks it; the delivery issues hold the acceptance boxes. **Nothing in this plan is built yet except the button design (#334, PR #335).**

## Dictionary

- **Welcome page**: step 0 of the user flow (page type `welcome`). Not "landing page", which is the existing marketing feature (`/admin/landing-pages`).
- **Welcome page screen**: the screen on the welcome page. It shows the default slideshow's setup (the real QR code with the real URL, the real frame, one image) in exactly the same design and layout as the default slideshow. "Giant", "virtual" and "big" screen mean the same; any other screen is named by where it is.
- **Default slideshow**: a new slideshow every event gets automatically, with the elements of items 1 to 5. **Videowall layout**: the existing admin-made layouts (`slideshow_layouts`) with one or many contents in parallel.
- **Global defaults**: the central inventory of building bricks (sample selfies, stadium backgrounds, QR texts), as library items in the existing Libraries section of the admin.
- **User**: anyone who goes through the flow, of any type. There is no difference between types; every user identifies themselves and gets the same experience.
- **Photo window**: the area of the default slideshow's stage in which photos are shown. **Sample selfie**: a library image cleared for commercial use, standing in for a user's photo. **QR text**: the words next to the QR code. **URL text**: the big written address under the photo window.

## Main rule (item 18)

Every element is generated automatically into a ready-to-go default, and the editor can always replace it. An event's own item always wins. Existing selections are never deleted. The existing system is read and checked before anything is built, and improved, never broken (item 20).

## How the work is delivered

Each delivery issue is one package: its acceptance boxes are ticked only when verified, and what is not verified is said plainly. Every pull request names its issue and the item numbers; the issue gets a comment saying what shipped and how it was checked; the documentation and the dictionary are updated in the same change; the global switch (item 26) decides when defaults reach existing events.
